Mały Matematyk

Model 135M nie musi umieć liczyć. Wystarczy, że umie przetłumaczyć zadanie na równanie.

Problem

  • Małe modele rozumieją treść zadania, ale źle liczą.
  • Typowa odpowiedź: dobre rozumowanie, zły wynik w ostatnim mnożeniu.
  • Standardowa rada to „weź większy model”. Nas interesuje odwrotny kierunek: mniej parametrów, ten sam albo lepszy wynik.

Rozwiązanie: podział pracy

1. LLM tłumaczyZadanie → jedna linia EQ: … = … z niewiadomą x. ~20 tokenów, zero liczenia.
→
2. Solver liczyParser + przeszukanie siatki + bisekcja. Wszystkie pierwiastki rzeczywiste, wybór właściwego.
→
3. WeryfikacjaPodstawienie, residuum. Błąd wraca do modelu jako feedback, model poprawia równanie.

Ta sama idea co w badaniach „AI dla matematyki i fizyki”: sieć proponuje kandydatów, twarda matematyka ich sprawdza (np. DeepMind, Discovery of Unstable Singularities, 2025).

Przykład

Kamień rzucony poziomo z prędkością 15 m/s z klifu 20 m. Jak daleko upadnie? model › EQ: 20 = 0.5*9.81*(x/15)^2 solver › pierwiastki: -30.29, 30.29 → x = 30.29 m (residuum 1e-15)
model › EQ: 0.5*m*x^2 = 4 solver › unknown symbols: m. Substitute the given numbers… model › EQ: 0.5*200*x^2 = 4 solver › x = 0.2 m

Wyniki: 34 zadania (12 równań, 22 z fizyki)

LLM liczy sam (CoT)LLM + solver

Ładowanie wyników…

Dlaczego lokalnie

  • Całość działa w przeglądarce: transformers.js, WebGPU albo CPU (WASM), wagi 4-bit.
  • Bez serwera, bez API, bez kosztów za token. Zadania nie wychodzą z komputera.
  • Tryb z solverem generuje kilkanaście razy mniej tokenów niż chain-of-thought, więc jest też szybszy.

Co dalej

  • Układy równań: model oddaje kilka równań, solver Newtona je rozwiązuje.
  • Fine-tune 135M tylko na tłumaczenie zadań → równania (zadanie jest wąskie, więc mały model wystarczy).
  • Polski: dotrenowanie na polskich zbiorach zadań maturalnych.
